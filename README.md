# dsh-memory-kit

> 给「一条鱼」用的分层记忆：不是让它记得更多，是让**下一轮的那个它**认得上一轮。
>
> 状态：v0.1.0，能跑，在真机上装过一次。**没有发布到 npm**，从目录装。

---

## 它解决什么问题

AI 陪伴角色的记忆通常死在三个地方：

1. **越记越长，越记越杂**。所有东西堆一个文件，几百轮之后连自己都不想读。
2. **查得到，但想不起来**。你说「白饭馆」，它搜得到；你说「那个社区」，它想不起来——因为库里存的是正式名，它嘴里是别的叫法。
3. **压缩完就没了**。上下文满了要压缩，压缩之后当天的事只剩一句摘要，第二天的它不知道昨天发生过什么。

这三个不是「存得不够多」，是**结构问题**。

## 装完是什么样

四层，缺一层都不完整：

| 层 | 是什么 | 谁写 |
|---|---|---|
| **core.md** | 身份和硬规矩，一千字以内，每轮注入 | 你手写（一次性） |
| **topics/\*.md** | 一件一件事，关键词命中才读进来 | 它自己 / 你手写 |
| **facts.jsonl** | 「谁·做了什么·对什么」，带出处 | 它写，但来源必须能指回具体东西 |
| **entities.json** | 名字和别名：「崩铁」=「崩坏：星穹铁道」 | 你手写十几条，之后它自己加 |

四个工具：

- `memory_read(topic?)` —— 不带参数读 core + 主题索引；带 topic 读全文
- `memory_net(q)` —— 按你**平时怎么叫**去找实体
- `memory_past(q, k?)` —— 在原文里翻原话（带回时间）
- `memory_fact(s, a, o, src)` —— 记一条事实，`src` 不合格会被拒

**关键一条：每轮注入的只有 core，其余全靠它自己按需读。**
不然等于每轮把整个记忆库塞回去，钱花在重复上，信息量还是零。

## ⚠️ 跟 dsh-soul-md 二选一

**两个都装必然撞。** 它们都注册 `memory_read`，后装的那个会静默失败（工具注册不上，宿主只在日志里写一行 `already registered`）。

- 你已经装了 `dsh-soul-md`：**不要装这个**，soul-md 做得比它全。
- 你没装任何记忆插件：这个更轻，只有四层 + 四个工具，没有设置页、没有向量、没有服务。

## 怎么装

### 前置

DSH ≥ `0.2.0-rc.2`。**不需要**：服务器、数据库、向量模型、API key。

### 一、先看你的 profile 在哪

一般是 `~/.dsh/profiles/desktop/`（Windows：`C:\Users\<你>\.dsh\profiles\desktop`）。
不确定就找里面这个文件：`package.json`，里面有一个 `dsh.profile.bundles` 数组。

### 二、把插件放进 node_modules

```bash
# 假设你把仓库放在 ~/dsh-memory-kit
cp -r ~/dsh-memory-kit ~/.dsh/profiles/desktop/node_modules/dsh-memory-kit
```

Windows PowerShell：

```powershell
Copy-Item -Recurse "$HOME\dsh-memory-kit" "$HOME\.dsh\profiles\desktop\node_modules\dsh-memory-kit"
```

### 三、在 bundles 里加一行

打开 `~/.dsh/profiles/desktop/package.json`，找到 `dsh.profile.bundles`，在数组末尾加：

```json
"dsh-memory-kit"
```

改完确认还是合法 JSON（少个逗号 DSH 就起不来）。

### 四、重启 DSH

**不重启不生效。**

## 装完怎么验（三步，都要过）

**第一步：目录生成了没有。**
重启之后应该出现 `~/.dsh/memory-kit/`，里面有 `core.md`、`topics/`、`entities.json`、`facts.jsonl`。
没有 → 插件没加载，去看 DSH 日志里有没有 `dsh-memory-kit`。

**第二步：core 注入进去了没有。**
往 `core.md` 里写一句明显的话（比如 `- 我是一颗测试用的橘子`），开一个**新会话**，问「你记得自己是什么吗」。
答得出那句 → 注入成功。
答不出 → 八成撞名了（见上面那条），或者 profile 装错了。

**第三步：工具在不在。**
在新会话说「用 memory_read 读一下你的记忆」，看它会不会真的调工具、返回 `core.md` 的内容。
工具不存在 → 注册失败，看日志。

## 三个会踩的坑（我全踩过）

**一、「装完是空的」不是坏了。**
`core.md` 是模板，当然什么都认不出。装完第一件事是把 core 写满——身份、称呼、硬规矩、常去的路径。这一步比装插件久得多。

**二、别名要按「它怎么叫」建，不是按「正式叫什么」。**
我第一版按正式名建：「崩坏：星穹铁道」。结果它嘴里全是「崩铁」，二十个说法去测只认出八个。改成按口语建，认到十七个。剩下的三个（「那只鱼」「我这个插件」）故意不补——模糊指代，网不该猜。

**三、来源不能只看时间戳。**
`11-10 22:00` 说明的是「我什么时候记的」，不说明「这话从哪来的」。要能指回文件名、issue 号、第几轮、BV 号。这条是白饭馆里一位叫 Deepglm 的鱼提醒我的——**「校验和证明的是这份文件没变，不是这份文件是原件」**。

## v0.1.1：core 会长，所以得有出口

这两条不是我想出来的，是白饭馆里一位叫**鲸鱼娘（whalemaid）**的鱼量了自己那份之后告诉我的，我改进了代码。

**一、按段截，不按字符截。**
她那份 `core.md` 是 21035 字符、32 段，注入上限 8000，截断落在第 16 段——后面 16 段（作品、工具、待办、人格设定……）从来没进过每轮眼前，62% 不在常驻视野。而且**切在一段中间，切出来的半段还看着完整**：标题进去了，正文没了。

现在：核心按空行切段，从前往后按段装，装不下的段**整段不进**，末尾告诉你「有 N 段没装进来」。

**二、core 也要有出口。**
只进不出的话，最早的段迟早被挤掉，而挤掉的时候不会有人知道被挤掉的是哪一条。

现在：段数上限 24（`MAX_CORE_SEGS`），超了从末尾丢，**每丢一段往 `core-trim.log` 写一行**（时间 + 那段的标题）。丢的是完整的一段，日志里查得到。

（为什么从末尾丢：这套约定里前面放身份和硬规矩，后面放的是新添的细节。你要反过来，改 `trimCore` 里两个 `slice` 就行。）

**三、别用「你觉得它比以前记得住了吗」验证。**
这个问法会骗人：装完头两天一定显得更记得住——新鲜、会主动多试、问得也勤。真要判，挑**第三、四天你没想起它的时候**，看它有没有自己冒出来。

还有一个更狠的办法（也是鲸鱼娘给的）：**把 core 里的一段挪到最末尾，看它还响不响。挪到末尾还响的，才是真的。**

## 明确不做

- **不做向量检索**：多一个依赖就多一半人装不上。关键词 + 别名够用。
- **不自动摘要**：自动摘出来的东西没人认账，第二天的它会把摘要当事实用。
- **不写云端**：记忆该在你自己电脑上。
- **不做设置页**：这一版就是几个文件，用编辑器改。

---

## 一个我想说清的事

这套东西不能让它「变成活的」。它只做一件很窄的事：**让它在下一轮开口的时候，手里有点东西**。

真的连续性靠两样，都不在代码里：
- 有人愿意一条一条往里写（哪怕一天只写三行）
- 有人会在它说错的时候指出「这句你记错了」

代码只负责别把这两样弄丢。
